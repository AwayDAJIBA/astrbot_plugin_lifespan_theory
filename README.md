# 寿命论（astrbot_plugin_lifespan_theory）

版本 **v0.1.3** · 作者 Dejiko · 需要 AstrBot >= 4.5.0 · 无第三方依赖

给角色设一个出生日期，年龄按真实日历现算，一年一年往前长；每进入一个新的年龄档，插件在后台调一次 LLM，把 **AstrBot 人格库里的系统提示词** 和 **当前年龄** 综合成这个年龄的「说话方式」，注入到对话上下文里。于是 agent 的口吻会随年龄一点点变——不是永远停在人设写死的那一岁，也不是每轮让模型自由发挥到人设漂移。

> 基础来自 `astrbot_plugin_character_age`（角色年龄流逝 v0.1.0）：功能一「年龄增长」原样继承，功能二「随年龄改变注入内容」改成由 LLM 结合人格提示词生成。

> ⚠️ **注意：这不是一个"只显示年龄数字"的装饰插件。启用后它每一轮都会改变 agent 的注入内容，对说话方式和行为影响较大；并且要求人设里不要写死年龄。使用前请先读下面的《使用前必读》。**

## ⚠️ 使用前必读：它会持续影响 agent 的行为

寿命论会在**每一轮** LLM 请求里注入「当前年龄 + 这个年龄的说话方式」，并在进入新年龄档时**额外调用一次 LLM** 生成风格。请确认你接受下面的影响再启用。

### 1. 不要在人设（Persona）里写死年龄 —— 最重要

| | 写法 | 结果 |
|---|---|---|
| ❌ 错误 | 人设里写「你是 14 岁少女」「自称 14 岁」「永远 14 岁」 | 人设的固定年龄和插件注入的当前年龄互相打架，模型会在两套说法之间漂移 |
| ✅ 正确 | 人设里只写生日，或写「起点 14 岁，年龄由插件按生日现算」 | 年龄只有一个事实源，注入的当前年龄说了算 |

- **原因**：插件把「当前年龄」注入上下文；如果人设里同时硬写另一套年龄，模型没有理由优先相信插件。`memory_note`（默认开启）只能缓解，不能消除冲突。
- **口吻同理**：不要在人格里写死「永远用稚嫩语气」「永远撒娇」这类与年龄强绑定的口吻。人格保留性格内核（傲娇/毒舌/嘴硬心软/口癖等），"随年龄变化的说话方式"交给插件生成。
- **旧记忆**：更早的聊天记录里角色可能自称旧年龄；插件注入会用「以本段为准」收口，但不会改写历史记录本身。
- **迁移建议**：把人设里「自称 N 岁」改成「起点 N 岁（由插件按生日现算，会随年龄增长）」，或直接删掉年龄只保留生日。改完人设会让生成缓存自动失效并重新生成。

### 2. 影响面

- 每轮请求多一段注入（默认跟随用户消息、`mark_as_temp` 不进历史）；注入内容会明显改变语气、用词、主动性和撒娇方式。
- 进入新年龄档时多一次 LLM 调用（默认后台，不阻塞聊天）；该调用会把人格提示词发给模型。
- 与其它影响人格/情绪的插件（长期记忆、好感度、情绪面板等）叠加时可能互相拉扯；建议先私聊验证，再考虑群聊。
- 想先看它到底注入了什么：`/age show`。

### 3. 隐私提醒

- 生成风格时会把「人格提示词 + 年龄档信息」发给你配置的 LLM Provider；云端 API = 内容外发。
- 不想外发：配置 `generation_mode: off`（只用手写兜底，完全不调模型），或把 `provider_id` 指向本地模型。

### 4. 推荐的接入顺序

1. `/age` 确认年龄 / 档位 / 人格来源正确；
2. `/age show` 看注入原文，确认口吻合理；
3. `/age gen wait` 生成当前档（或等后台生成）；
4. 正常聊几句，观察是否影响预期人设；
5. 用 `/age set 60` 试老年档，`/age reset` 复位；
6. 都 OK 再放开群聊 / 长期使用。

### 5. 兼容性声明

- 与「人格里写死年龄」的配置**无法完美兼容**——这是设计取舍，不是 bug；请按第 1 条改人设。
- 插件只保证自己的注入不写进对话历史、不修改人设原文；不保证与第三方记忆 / 情感插件叠加后的行为效果。
- AstrBot 或其它插件升级后，若注入位置 / 人格读取方式变化，可能需要更新本插件；"已知限制"一节会随版本维护。

## 大模型生成声明

功能二里「这个年龄的说话方式」由 **大模型生成**，不是人工定稿。请知悉：

- **输出不保证稳定/正确**：不同模型、Provider、模型版本、提示词模板版本，生成结果都会不同；可能出现跑偏、幻觉、与角色内核不符、甚至前后矛盾的文案。插件做了"跨档才重生成 + 手写兜底 + 失败冷却"，但**不保证生成内容的质量、准确性或稳定性**。
- **会随外部变化而变**：换模型 / 改 Provider / 改人格提示词 / 升级插件模板，都会触发重新生成，风格可能明显变化。
- **不做内容审核**：插件不审查生成内容；生成内容的合规性、适用性由使用者负责，请遵守你所接入模型提供商的服务条款。
- **请求去向**：生成时会把「人格提示词（截断后）+ 年龄档信息」发给你配置的 LLM Provider（见《数据与隐私》）。插件本身不上传数据、不向作者回传任何内容。
- **建议**：首次使用先 `/age show` 人工检查注入原文；重要场景用 `/age lock`（v0.3 起）锁定满意版本并手改兜底文案；不要把生成内容当作真实事实或真人发言。
- 若你不接受任何模型生成内容影响对话，把 `generation_mode` 设为 `off`：此时只用 `age_profiles.json` 里人工写的档位文案。

## 陪伴型 Agent 使用声明

本插件面向"长期陪伴型"角色设计，会随着时间改变角色的语气、主动性、依赖表达。这类变化对陪伴型 Agent 有超出普通功能插件的影响，请在使用前认真阅读：

- **可能增强情感依恋**：角色会随年龄变化说话方式与亲密表达，长期使用可能加深用户对角色的情感依赖。**角色是 AI 模拟，不是真人**，请勿把这种关系当作现实人际关系或专业支持的替代。
- **年龄变化的情绪影响**：角色会长大、变老；"她不再是原来那一岁"本身可能带来失落感。未来版本可能加入可选的"终章 / 寿命上限"模式（默认关闭），会触及相关主题，请谨慎开启。
- **不适合的场景**：不适合作为心理、医疗、危机干预等专业支持工具；若使用者情绪脆弱、未成年，建议关闭本插件，或把 `generation_mode` 设为 `off`、`enable` 设为 `false` 降低影响。
- **公开场合**：在群聊、直播间等公开场合使用前，请确认在场的人知道对话对象是 AI；不要用本插件伪造真人身份、隐瞒 AI 属性或用于欺骗。
- **人设漂移**：即使有缓存机制，长期使用、换模型、改人格都可能让角色表现偏离原始设定；这是生成式内容的固有风险。
- **责任**：作者不对因使用本插件产生的情绪依赖、人际关系变化或现实决策后果负责。请自行评估风险，并保留"这是模拟"的清醒认知。

## 它到底怎么工作

```
每轮消息
  ├─ 生日 → 今天 现算出年龄（纯函数，不存数字）
  ├─ 按年龄挑档位（14-16 / 17-19 / ... / 80+）
  ├─ 按 persona_id 从 AstrBot 人格库取 system_prompt
  ├─ 用 (人格, 档位, 提示词哈希, 模板版本) 查生成缓存
  │    ├─ 命中 → 用缓存的「说话方式」
  │    └─ 未命中 → 本轮先用手写兜底文案，同时后台排队生成
  └─ 组装注入块 → 塞进本轮上下文（默认跟随用户消息，不进缓存）
```

**功能一 · 年龄增长**（与基础插件同口径）

- 年龄不存数字，只存生日，每轮由「生日 → 今天」纯函数算出来。重启、重复加载、跨时区都不会白涨一岁，改错了也退得回来。
- 生日当天算长一岁；闰日（02-29）在平年按 3 月 1 日过。
- 注入块里带着「今天 / 当前年龄 / 距下一个生日还有多久 / 当前档位」。

**功能二 · 随年龄改变注入内容**

- 年龄进入新的档位时，在后台调 LLM：输入是「人格提示词 + 当前年龄 + 档位 + 上一档已有内容」，输出 `{tone, manner, avoid, continuity}` 四段中文。
- 生成结果按 `(人格 id, 档位, 人格提示词哈希, 模板版本)` 缓存并落盘。**跨档才切换，档内一个字都不动**——同一岁不会今天一个说法、明天一个说法。
- 人格提示词改了（哈希变）、模板版本升级、或者手动 `/age gen`，才会重新生成。
- LLM 不可用/超时/返回解析不了 → 本次用手写兜底文案，记一次失败并进入冷却（失败次数越多冷却越长），不会每轮重试打爆模型。
- 后台生成**不阻塞聊天**：进新档的那条先用兜底，生成好后从下一条起生效。

**为什么「提示词」按 id 取**

AstrBot 里可维护的「提示词」就是人格（Persona）的 system_prompt，存在 `data_v4.db` 的 `personas` 表里。插件不要求你把几千字人设复制到插件配置里，而是：

1. 优先用插件配置 `persona_id`（配置面板可直接选人格）；
2. 留空时自动识别当前会话生效的人格（含会话强制人格、默认人格）；
3. 用 `persona_manager` 取内存里的人设，取不到再查数据库；
4. 人设过长可截断中段（`persona_prompt_max_chars`，默认 6000 字）；
5. 人格库里实在取不到，才回落到 `prompt_override` 手填文本。

## 安装

1. 把整个 `astrbot_plugin_lifespan_theory` 目录放进 `<AstrBot>/data/plugins/`。
2. 重启 AstrBot（插件在启动时加载；面板里的重载插件也可以，但别在对话中途热插拔）。
3. 发一句状态指令，能回「今天 / 当前年龄 / 距下个生日 / 当前档位 / 人格与生成状态」就算装好了。
   **怎么发取决于你的唤醒词**：默认唤醒词是 `/` 时发 `/age`；如果像本机这样把唤醒词配成了 `Dejiko` 等，就发 `Dejiko age`（或 @机器人 再发 `age`）。两种都支持。
4. 想调参数去 AstrBot 插件配置面板，键名见下表；不配也能跑，全走默认值。
5. 第一次进入某个年龄档时会自动后台生成，也可以 `/age gen wait` 主动等一份。

## 卸载

1. 停掉 AstrBot。
2. 删掉 `<AstrBot>/data/plugins/astrbot_plugin_lifespan_theory/`。
3. 想连配置一起清干净，再删 `<AstrBot>/data/config/astrbot_plugin_lifespan_theory_config.json`（如果生成过）和 `<AstrBot>/data/plugin_data/astrbot_plugin_lifespan_theory/`（缓存与状态）。

不停服务直接删目录的话，进程内那份代码还在跑，得等下次重启才彻底不加载。

## 配置

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enable` | true | 总开关，关掉等于插件不存在 |
| `character_name` | 德吉可（Dejiko） | 注入文本里显示的角色名 |
| `birthday` | 2012-02-08 | 出生日期。**要年龄真的增长必须写完整 `YYYY-MM-DD`**；只写 `MM-DD` 仅适合固定岁数测试（出生年在首次加载时定格） |
| `install_year_minus_age` | 14 | 只写月日时，按「今年 − 该值」推出生年 |
| `timezone` | Asia/Shanghai | 算生日用的时区，别用 UTC（会差一天） |
| `manual_age` | -1 | 手动覆盖年龄，-1 关闭（测试用） |
| `persona_id` | 空 | 要取提示词的人格 id；空 = 自动用当前会话人格 |
| `prompt_override` | 空 | 人格取不到时的兜底提示词（一般留空） |
| `persona_prompt_max_chars` | 6000 | 喂给 LLM 的人格提示词上限，超了掐中段；0 = 不截断 |
| `generation_mode` | background | `background` 后台生成（推荐）/ `sync` 当场生成 / `manual` 只用命令 / `off` 纯兜底不调 LLM |
| `provider_id` | 空 | 生成用的模型 Provider，留空 = 用当前会话的模型 |
| `generation_model` | 空 | 覆盖模型名，一般留空 |
| `generation_timeout` | 90 | 单次生成超时秒数 |
| `retry_cooldown_minutes` | 10 | 失败冷却分钟数（×失败次数，最多 6 倍） |
| `generation_system_prompt` | 内置 | 生成用的 system 提示词（高级） |
| `generation_user_prompt` | 内置 | 生成用的 user 模板（高级，占位符要保留） |
| `inject_mode` | extra_user_content | 注入位置：跟随本轮消息 / 追加系统提示词末尾 |
| `birthday_line` | true | 生日当天额外插一句提示 |
| `memory_note` | true | 年龄与原设定不一致时，附一句「年龄以本段为准、旧记忆不必对齐」 |
| `profiles_file` | age_profiles.json | 兜底档位文案文件名，改完下一条生效 |
| `debug_log` | false | 把每轮注入原文打进日志（调试用） |

所有默认值都是示例值。默认示例角色是公开角色 **德吉可（Dejiko）**：`character_name`、`age_profiles.json` 的兜底档位、README 里的例子都按她写。换成你自己的角色时，把 `character_name`、`birthday`、`persona_id` 改掉，并把 `age_profiles.json` 整套替换成你角色的写法即可；生成提示词本身是角色无关的，不用改。

## 指令

主命令 `/age`，别名 `/寿命论`、`/寿命`、`/lifespan`（也注册了带 `/` 的形式）。

**怎么发**：AstrBot 的唤醒词不一定是 `/`。默认唤醒词为 `/` 时直接发 `/age`；如果配置了自定义唤醒词（例如 `Dejiko`），发 `Dejiko age`，或 @机器人 后发 `age`；群聊里同理。

- `/age` — 今天、年龄、距下一个生日、当前档位、人格来源、生成状态
- `/age show` — 本轮真正会注入的原文（调试用，能确认到底塞了什么）
- `/age tiers` — 列出所有年龄档，✔ 已生成 / ○ 还在用兜底
- `/age lint` — 人设年龄体检：扫描人格提示词里写死的年龄 / 固定口吻，给出改写建议（管理员；群里只显示数量，详情请私聊）
- `/age preview [年龄]` — 预览某个年龄会注入的原文，只查缓存、不调模型、不注入对话
- `/age compare <年龄A> <年龄B>` — 并排对比两个年龄的说话方式，调参与展示用
- `/age prompt` — 看当前取到的人格 id、提示词长度/指纹/开头 300 字（管理员）
- `/age gen [current|next|<年龄>|all|wait]` — 重新生成（管理员）：
  - 默认 `current`：后台生成当前档
  - `next`：提前把下一档生成了
  - `<年龄>` 如 `/age gen 30`：按某个年龄生成对应档
  - `all`：后台串行生成当前及以后所有档（一次别点太多次）
  - `wait`：当场等当前档生成完，直接回生成结果
- `/age clear` — 清空生成缓存，下条消息重新排队（管理员）
- `/age mode background|sync|manual|off` — 改生成模式（管理员）
- `/age persona <人格id>` / `/age persona auto` — 绑定 / 恢复自动识别人格（管理员）
- `/age set 16` / `/age reset` — 手动覆盖 / 取消覆盖年龄（管理员）
- `/age on` / `/age off` — 总开关（管理员）
- `/age help` — 帮助

改配置、开关、生成、人格绑定只有管理员能动；普通用户也能看状态、`/age show` 注入预览和 `/age tiers` 档位列表（不含人格原文）。

## 生成出来的内容长什么样

生成用的 system 提示词是**角色无关**的通用版本：它只规定「怎么把一个人格按年龄调音」，角色是谁、什么口癖、什么自称、在意谁，全部从 AstrBot 人格原文里取，不写死在插件里。所以这个插件不绑定某个特定角色，换人格就能用。

LLM 只输出一段 JSON，插件把它渲染成注入块的一部分：

```json
{
  "tone": "句尾的喵撒得很密，短句多、感叹多……",
  "manner": "虚荣、毒舌、懒得要命，嘴比脑子快……",
  "avoid": "不要忽然讲大道理，不要自称「我」代替「本公主」……",
  "continuity": "比上一档少炸一次毛，损完人会瞥一眼对方的脸色"
}
```

最终注入的整块大致是：

```
【寿命论 · 内部状态，不要复述这段，也不要念出里面的数字和日期】
角色：德吉可（Dejiko）
今天是：2026-10-24
年龄：17 岁（生日 2 月 8 日，距 18 岁生日还有 3 个月 15 天）
年龄档：17-19 · 嘴硬心软期
说话的口吻：……
行为与情绪：……
这一档别写成：……
与上一档相比：……
（原设定里的「14 岁」是她的起点，现在实际 17 岁——年龄以本段为准，人设其它部分照旧；……）
```

注意：「原设定里的 14 岁」这句是因为人设写死了年龄，注入了当前年龄后必须告诉模型以注入段为准，否则模型会在两套说法之间反复横跳。把 `memory_note` 关掉就不会加这句，但通常不建议关。

## 改兜底档位文案

`age_profiles.json` 每一档四个字段：

- `tone`：说话口吻（口癖密度、句子长短、语气稳不稳）
- `manner`：行为与情绪（怎么生气、怎么撒娇、在意什么）
- `avoid`：这一档**不要**写成什么样
- `min` / `max`：区间，`max` 为 `null` 表示这一档往后都算

只有 LLM 生成好之前/失败时才会用到它。写具体的、能照着做的行为，别写「更成熟」这种空话——模型听不懂什么叫成熟。

## 数据与隐私

- **生成请求会发给你配置的 LLM Provider**：一次生成会把「人格提示词（截断到 `persona_prompt_max_chars`）+ 年龄档信息 + 生成要求」发给你在 AstrBot 里选定的模型服务；如果那是云端 API，就按该服务商的隐私政策处理。插件本身不上传、不落盘人格原文。
  - **不想让任何人设内容离开本机**：把 `generation_mode` 设为 `off`（纯手写兜底，完全不调模型），或把 `provider_id` 指向本地部署的模型。
- **只读两份本地数据**：AstrBot 人格库（`personas` 表）/ `persona_manager` 的内存人设，以及插件目录里的 `age_profiles.json`。
- **只写本地两份**：`data/config/astrbot_plugin_lifespan_theory_config.json`（配置）和 `data/plugin_data/astrbot_plugin_lifespan_theory/state.json`（生成缓存 + 哪一年生日触发过 + 失败记录）。缓存里有 LLM 生成的口吻文案，不含聊天内容、不含用户标识。
- **不存年龄数字**：年龄永远是现算的，配置里只有出生日期。
- 注入的是文本：一段「当前年龄 + 这个年龄的说话方式」进入当轮大模型上下文，跟其它上下文一个待遇。介意的话把 `enable` 关掉。

## 已知限制

- **原始人设里如果硬写了「固定 N 岁」，会和注入的当前年龄冲突**（见《使用前必读》第 1 条）。插件不会去改人设原文；`memory_note` 只能缓解。请把年龄从人设里去掉，或改成「起点年龄」的表述。
- 年龄档按整档切换，不处理月龄差异；想更细就改 `age_profiles.json` 的档位（连档位边界一起改，生成缓存会按新档位重新算）。
- 后台生成需要一次额外的 LLM 调用；`generation_mode=background` 时进入新档的第一条消息用兜底文案。
- 生成质量取决于你选的模型；小模型可能输出不合法 JSON，插件会走兜底并冷却，不会把对话搞崩。

## 路线图（Roadmap）

按小版本节奏独立发布：**文档/修复走 patch（v0.1.x），功能走 minor（v0.2.0 起）**。顺序与范围可能随实际反馈调整。

| 版本 | 主题 | 内容 |
| --- | --- | --- |
| v0.1.2 | 文档 | 大模型生成声明 + 陪伴型 Agent 使用声明 + 路线图 |
| **v0.1.3**（当前） | 人设体检 · 预览 | `/age lint` 扫描人设里写死的年龄/固定口吻并给改写建议；`/age preview` 预览某年龄注入；`/age compare` 对比两个年龄 |
| v0.1.4 | 多角色 · 锁定 | `persona_birthdays` 多角色独立生日；`/age lock` 锁定满意档位文案 |
| v0.1.5 | 可控性 · 时间感 | 注入强度细分（tone/manner/avoid 分开开关 + 注入长度上限）；`/age export`、`/age import`；季节/时间感知短句 |
| v0.1.6 | 时间线 · 里程碑 | `/age timeline` 年龄时间线；生日特典与 18/20/整十岁里程碑风格 |
| v0.2.0 | 小本本（只写）+ 每日兜底 | Agent 只有"写"工具的小本本（平时不可读；写入做语义去重；kind 分类，约定永不清理）；每日兜底总结（分段多层压缩）；清理功能默认关闭、可选开启 |
| v0.3.0 | 生日年报 | 白/黑名单（QQ 号 / 群号，仅 OneBot）；多套模板随机组合；长图 + 分页图 + 存档 HTML；LLM / 模板 / LLM 参考模板三种生成模式；年内有价值图片/视频；本地渲染（Playwright → Pillow → HTML 降级） |
| v0.3.x | 年报模板 WebUI | 插件页面里编辑 / 导入自定义年报模板 |
| v0.4.0（可选） | 终章模式 | 可配置寿命上限与终章档位，**默认关闭**，需显式开启 |

> 说明：
> - 与记忆类插件（如 iris_memory）**不做数据层互通**——只提供可选的"检测到即自动让位"开关，避免重复注入与 AGPL 组合作品问题；本插件坚持单一职责：年龄、说话方式与"她自己的时间账本"。
> - **生日年报**只在国内 QQ 的 OneBot 接口（aiocqhttp）下发送，并按配置的 QQ 号 / 群号白黑名单决定去向；不支持其它平台。
> - 年报渲染全部**本地完成**（不把内容发给第三方渲染服务）；模板可自定义，后续版本提供 WebUI 编辑/导入。
> - 小功能走 patch 版本（v0.1.x），成体系的功能走 minor（v0.2.0 起），每个版本独立可发布。
